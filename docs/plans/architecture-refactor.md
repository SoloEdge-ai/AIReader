# AIReader 0.2 整体重构实施方案

状态：已接受，实施中。实际基线为 `d7fcbc21ea9c3f428ed81160849119d3f27e72cd`（main，2026-09-24）。本文件描述目标，不表示功能已完成；当前行为以 [文档入口](../README.md) 链接的文档为准。

## 交付规则

- 一个长期分支 `codex/architecture-refactor`、一个 Draft PR，最终整体 squash 合入，不向 main 推送。
- PR 更新自动检查并生成安装包、便携 EXE 和校验和。可体验阶段由维护者手动发布预览 Release，非每次推送发版。
- 预览使用 `0.2.<工作流序号>`，标记 prerelease，不更新 Latest；合入 main 后正式发布。安装标识及当前用户安装位置不变。
- 不趁本次重构增加跨书项目、云同步、OCR、触控正式支持或解除编程工具隔离限制。
- 工具盘拖动问题纳入交互重构验收，不先打补丁。尚未完成的部分必须在进度表和验证记录中标明。

## 产品与 UI

保持以单本 PDF 为固定阅读轴的共享白板；左侧为可收起的导航／搜索／材料，中央为 PDF、卡片、笔迹和关系，右侧为可收起的问答。不再设置阅读和整理模式。

统一颜色、间距、字体、圆角、边框、焦点、图标和浮层层级。保持中性、紧凑、浅／深／系统主题，PDF 不反色。图标 18–20 px，工具点击区至少 36 px。导航初始宽 240 px、范围 220–320；问答初始宽 380 px、可调整；窄窗口采用抽屉。工具盘、对象条、选区条、菜单、颜色面板复用组件，不各自监听 Escape。

支持卡片内直接编辑和工作区中的展开编辑层，展开时仍可使用问答。原文来源与个人评论分离。指针、文字选择、临时平移、绘画、编辑器输入和中文输入法不得互相抢占。右键临时平移、Ctrl＋滚轮锚点缩放和 PDF 避让保留。

## 统一笔记和删除语义

`Note` 是唯一富文本内容实体，材料列表、卡片和展开编辑器引用同一内容及草稿；空间位置是单独的 placement，不再保存一份卡片正文。每本书每个 Note 最多一个 placement；重复放置定位原卡片。复制笔记创建独立内容。

高亮／下划线等标注不自动创建空笔记；用户显式写评论时才创建并关联 Note。

| 操作 | 目标语义 |
| --- | --- |
| 移除画布卡片 | 保留 Note |
| 删除 Note | 删除 placement 和相关关系；保留并解除关联的源标注 |
| 删除源标注 | 保留已有 Note 和其来源说明 |
| 删除摘录 | 保留用户评论及来源说明，不伪装仍存在的摘录 |
| 撤销跨实体操作 | 同一事务恢复内容、位置与关系 |

## 模块与状态边界

- Electron：窗口、系统文件入口和进程生命周期，不拥有业务数据。
- Renderer：UI 与交互，无 Node 权限，通过类型化 HTTP／事件客户端访问 Core。
- `BookEditingSession`：每书统一的实体缓存、草稿、提交队列、冲突、撤销／重做；页面和编辑器不再维护多套保存链路。
- 工具控制器：临时工具、手势、编辑状态和取消，不混入持久实体。
- `workspace-engine`：纯坐标、几何、命中、避让与选择，无 React、DOM 或 Node 依赖；PDF 适配器提供 viewport 转换。
- Core：用例协调、事务、书籍隔离、资源和 AI；数据库不通过 Library 的公共 store 泄漏给全部服务。
- 共享协议：按领域拆分，模块不能回引 barrel index；事件是可区分联合，不以 unknown 传全部载荷。聊天逐步改为事件驱动，断线可重新获取快照。

以真实行为边界划分模块，不按文件行数机械拆分，不引入只转发参数的层。无需新增全局状态框架。

## 数据、命令与退出

目标数据库 v5、归档 v3、HTTP `/api/v2`。当前本机旧测试数据已获准删除，无需迁移或备份旧内容；但清理必须作为本机独立交付步骤，仅针对 AIReader 内容，保留独立账号、运行组件和外部原始 PDF。安装器不能无条件清理所有用户的数据。后续 0.2 预览升级必须保留新的数据。

SQLite 按实体和引用存储；富文本文档、单笔点集可以使用 JSON，不能继续用整个工作区 JSON 覆盖所有对象。源坐标绑定 PDF 指纹、物理页和 PDF 坐标；跨页笔迹仍是一个逻辑对象。

命令包含 bookId、commandId、payloadHash、expectedContentVersion 和类型化变更。Core 校验实际 payloadHash；同 ID 不同载荷拒绝；相同请求重试返回原始提交回执，而不是当前工作区。对象、关联和逆操作由事务提交，滚动视野独立于内容版本和撤销历史。失败保留草稿并显式允许重试／处理冲突，不静默覆盖。

关闭应用先提交 renderer 草稿，再停止 Core 任务、Worker、Codex，最后关闭数据库和窗口。失败保留窗口与草稿，不直接强杀 Core。归档 v3 保存重建工作区需要的对象和资源，但不包含凭证或整段聊天；明确拒绝其他版本。

## AI 和来源

继续在添加时冻结个人材料，在发送时冻结阅读范围、模型与强度。修改原卡片不改变已加入或发送的材料。服务公开的 reasoning summary 可显示；不要求或伪造隐藏思维链。只有 Core 验证的原文证据产生引用；个人笔记、绘画和 AI 笔记保留来源分类。

保留约 12,000 tokens 的应用文本预算、20 项材料和合计 4 张图片限制；不得把旧图片和材料无限重发。未选择的关联对象不得偷偷进入模型请求。

## 测试策略

优先测试真实 Core HTTP、SQLite、PDF 提取、上下文组装和 UI，仅 mock 外部 Codex 进程。新增行为先有失败的边界测试，再最小实现；保留安全和数据完整性测试，因规格变更修改测试时写明原因。

数据测试包括跨书拒绝、重复命令、载荷冲突、过期版本、原子删除／撤销、重启恢复、断网重试和退出草稿。UI 覆盖浅深主题、1280×720／1440×900／1920×1080、100%／150%／200% 缩放、键盘与输入法。压力样本为 516 页、500 卡片、1000 关系、5000 对象、250000 笔迹点；记录机器、帧耗时、长任务和资源占用，不仅写“正常”。

公共 CI 只用生成样本和模拟账号。用户 PDF、凭证、数据库及其派生截图不得提交。最终提交包括实际 PR、构建版本、校验和、真实 UI 截图、测试结果、已知限制和同步的开发文档。所有阶段完成并审查后才整体合入。
