# 摘录评论统一验证

状态：阶段 2 增量切片；不代表整个 0.2 重构完成。

## 行为

- 生成 PDF、临时 SQLite 和真实 Core HTTP：创建旧摘录卡片及纯文本评论，首次请求在同一事务中创建 Note、清空卡片副本并绑定 noteId；重复请求返回同一 Note。
- 修改 Note 不改变卡片原文；删除／恢复 Note 解除／重建来源卡片绑定，原卡片仍在。
- 材料选择同时保留 book-excerpt 和 user-note 两类，个人评论不作为作者原文引用。
- 工作区归档恢复副本重映射 Note、来源卡片和资源 ID；先删除摘录卡片再归档，孤立评论和冻结来源仍保留。单笔记 Markdown 包含来源和个人内容区别。
- 区域卡片转换后即使删除原卡片，归档副本仍保留来源 PNG，并重映射资源 ID，受控资源接口可读取。
- 跨书卡片 ID 请求被拒绝；源内容、指纹和图片来源由 Core 校验。
- 旧个人卡片通过相同端点转成 Note；卡片 title/text/comment 清空但内容保留在 Note。删除／恢复 Note 时位置随同处理。界面不再继续写旧纯文本正文路径。

- `pnpm test`：28 文件／45 测试通过；之后补的区域孤立资源与原子失败用例分别目标复跑通过。`pnpm typecheck`：通过。
- `pnpm test:reader-ui`：19 项通过，包含摘录、旧个人卡片及工具盘手柄拖动。
- `pnpm desktop:windows`：本机 Windows 11 build 26200 上构建成功，生成本地 0.1.0 Setup 和 Portable，打包 Core smoke 通过；不是预览 Release，也未安装到用户目录。构建保留现有 pnpm shim Node 22 引擎告警、PDF.js 资源和大 chunk 告警；类型和测试使用 Node 24.19.0。
- 已查看生成 PDF 的 `test-results/excerpt-comment-note.png`：原文与个人评论同时可见；选中源卡片时评论显示紧凑预览，点击“编辑评论”进入展开编辑，避免窄卡内富文本工具遮住原文。图片仅存本地测试结果，未提交用户书籍内容。
- Spec 和 Standards 只读审查发现合法旧卡片大量短行可被转换为超过 Note 上限的富文本，造成之后无法保存／导出；先补失败 HTTP 用例，再在保存前校验 Note 文档并对高开销换行编码退化为单文本节点。目标测试与类型检查通过。其他阻断意见未发现。
- 构造仍超过 Note 约束的旧正文（大量需 JSON 转义的控制字符）会原子拒绝转换：原卡片字段与 Note 数量均保持不变。
- 工具盘手柄在独立浏览器夹具中可拖至左侧并持久停靠；尚未据此声称真实书籍界面中的拖动体验已经验收。
- 旧纯文本摘录评论与个人卡片按需转移（首次点击编辑），不是数据库启动时批量迁移；尚未点击的旧记录保留可读。
- Note 和工作区目前仍分别保存；统一的 BookEditingSession、命令回执和归档 v3 尚未实现。
