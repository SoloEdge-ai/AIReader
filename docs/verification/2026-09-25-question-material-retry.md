# 提问材料并发重试与记录所有权

状态：本地验证，尚未推送到 Windows CI；不代表整体 0.2 重构完成。

新增真实 Core HTTP 测试，以生成 PDF 创建区域图片卡片，再同时发送两次相同的“加入提问”请求。修复前两个响应返回不同 materialId；测试先失败，证实图片文件读取期间的并发请求绕过了原先只在开始时检查的 requestId。修复后两次响应返回同一冻结快照，数据库中只有一份材料记录，磁盘只有一个材料图片目录；同 ID 不同载荷仍被拒绝。

`QuestionMaterialRepository` 现在拥有按书籍／会话读取、requestId 回执、原子创建、提交标记及过期回执清理。`QuestionMaterials` 仍负责选择内容、原文／个人材料分类、来源版本核对、图片验证和文件收尾。第二个并发请求若在图片 I/O 后才发现首个请求已提交，会清理自己刚生成的文件，并返回首份快照，不把它写成另一份材料。真实 SQLite 仓储测试还注入回执写入失败，确认材料记录同时回滚，跨书相同 requestId 互不污染。

本地 `pnpm typecheck`、两项材料 HTTP 定向测试、仓储测试及全量 Core 测试（38 文件／59 项）已通过；Windows CI 尚待本提交推送后验证。测试仅使用生成 PDF 与图片，无用户书籍或账号材料。
