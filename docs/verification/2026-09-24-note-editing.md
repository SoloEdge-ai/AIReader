# 共享笔记编辑切片验证

状态：重构阶段 2 的前置切片，未完成统一卡片数据模型。沿用分支 `codex/architecture-refactor` 和原 main 基线；此前 Draft PR #24 的 Windows Build and verify 已成功，发布 job 按 PR 策略跳过。

## 已执行

- 双编辑器的首个 Playwright 测试先复现失败：修改标题后第二处仍显示“新笔记”。会话与共享编辑器实现后通过，验证正文双向同步和刷新后持久化。
- 展开编辑入口测试先因入口缺失失败；实现后通过，验证问答与笔记同时可用。
- 保存失败时两处草稿保留、关闭被阻止、重试成功后可 Esc 收起。
- 旧请求成功但响应丢失时继续输入，核对已提交的旧请求后继续保存新稿，刷新后新稿保留。
- 有脏草稿时普通刷新不暗中接受远端新 revision；常规重试仍报告冲突，仅用户明确覆盖后替换远端内容。
- 测试使用真实 Core、临时 SQLite、生成 PDF；只在 HTTP 网络边界模拟失败／丢失响应，不 mock 内部会话或存储。

- 类型检查（含架构依赖与文档链接门禁）通过；完整 Vitest 25 文件／42 测试通过（62.39 秒）。
- Playwright 12 项通过（30.1 秒），包括 7 项笔记交互及 5 项工具盘／菜单回归；补充链接表单 Esc 断言后单项重跑通过。
- 已检查生成 PDF 的实际界面截图：展开笔记与问答并存。截图仅保存在本地 test-results，不含用户书籍。
- Windows Portable／当前用户 Setup 打包通过（本地开发版本 0.1.0，未发版）；打包后的 win-unpacked 程序在 100% 缩放通过批注、自动保存恢复、退出保护、重开、跨页、旋转及缩放锚点回归，使用独立测试数据目录。
- 本机通过显式 Node 24.19.0 启动检查；嵌套 pnpm shim 输出 Node 22 engine 警告，构建仍成功。现有 PDF.js 样式资源与 bundle 大小警告未在此切片处理；未声称完成所有 DPI 或性能验收。

## Standards 审查

首轮发现保存与刷新并发时，新建笔记可能不出现在列表，以及被动编辑器可能撤销另一处同步正文。新增 renderer 回归均先复现失败，再修复：最新读取被保存打断时重新读取；镜像事务不进入本地撤销历史。独立复核无遗留阻断问题。

## Spec 审查

首轮同样指出刷新丢弃问题，并发现链接表单 Esc 未处理。已由表单消费 Esc、保留展开编辑器并恢复正文焦点，输入法组合期间不抢占。独立复核无新增明确问题；完整 IME、统一历史仍未完成。两路复核为静态审查，测试由主任务实际执行。
