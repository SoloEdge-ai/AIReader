## 问题与修正

在接入后续评论流程前，检查发现 Notes.save 在 SQLite 外层事务提交前就广播事件。恢复 Note 后若原连线端点缺失，数据库整体回滚，但 WebSocket 已发出活跃 Note，可能使客户端显示不存在的恢复。

新增真实 HTTP／WebSocket 回归：删除笔记位置及其连线端点，再请求恢复。首跑 HTTP 返回 400、数据库保持删除，但接收到 note 事件，测试失败。`NoteTransactions` 接管记录写入和同步事务中的事件快照，成功提交后发布，失败丢弃。修正后失败恢复无事件；补回端点后有效恢复仍发出 note／workspace，并能通过 HTTP 读取完整位置。

没有 mock 内部存储或事务。使用 WebSocket ping／pong 顺序屏障检查已发送事件，不用固定延时猜测通知是否到达。数据均为临时库和生成 PDF。
