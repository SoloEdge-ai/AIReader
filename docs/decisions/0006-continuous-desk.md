# ADR 0006：连续阅读桌面与共享浮窗

状态：实现中，替代 ADR 0005 的固定双栏视觉与工作台内整页编辑决定；独立 PDF 坐标、Core 所有权和书籍编辑会话保持有效。

## 已认可的交互

2026-09-26 用户认可本地交互原型，并要求正式实现时保留扩展边界。默认空间桌面 B：PDF 是有边界、可移动缩放的文档对象，内部连续阅读；卡片位于同一桌面。连续并排 A 作为可切换布局，保留原文与整理材料各自滚动。两种布局共享内容与选择，布局变化不复制材料。用户不要求兼容先前笔记和工作区数据。

## 模块与所有权

- `features/desk/useDocumentObject`：桌面单位下的文档矩形和临时手势；释放时保存阅读偏好，取消不保存。桌面相机投影文档矩形，PDF 自身缩放再乘桌面缩放。
- `features/desk/useExcerptDrag`：命中真实 PDF 选区后冻结全文及 PDF 锚点。屏幕落点交由工作区转换为桌面单位；无效释放、Esc、失焦与卸载取消，不生成摘录。
- `ui/floating-window`：仅拥有矩形约束、八方向缩放、拖动、键盘和取消。AI 和笔记共享此能力；业务组件分别拥有会话与保存屏障。浮动笔记只挂载一份 Tiptap，不遮断 PDF 和卡片。
- `workspace-engine/contact`：纯几何的近邻判定与凹形纸面桥。20 单位预览、8 单位释放附着、44 单位分离迟滞。常量是本产品设计，不声称来自 LiquidText 源码。
- `features/workspace/groups`：将释放后的卡片位置和组归属组合成一次工作区内容变更；仍经既有命令队列和 Core 事务保存。`presentation=cluster` 的桥根据组成员和相邻几何派生，不创建表示证据或因果关系的语义关系。
- 卡片选择继续由工作区持有，支持 Ctrl／Shift 和显式复选模式。问题草稿仍由 QuestionDraftStore 按书／会话持有。每个选中对象冻结为一条材料记录，可分别移除；已加入对象不因再次选择或编辑被替换。

## 数据与扩展

新增 `deskLayout`、`documentRect`、`noteWindow` 阅读偏好；窗口和视口不进入内容历史。主题组增加可选的 `presentation`，普通框选主题仍为框式组。现有 JSON、命令差异、Core 校验、归档与撤销承载这一字段；不增加第二条写入通道，也不重写历史回执。

B 的文档对象与卡片使用同一桌面相机，内部 PDF 继续使用原始 PDF.js 坐标。A／窄窗改变呈现方式而不卸载文档。以后增加多文档时应将文档对象身份与矩形纳入项目模型；首版本书只有一个文档矩形，不提前引入项目或通用画布框架。

## 验证

真实 Core HTTP 检查 cluster 保存、重启及逆操作；浏览器用生成 PDF 验证 A／B、原文直接拖出、材料多选冻结、笔记浮窗与重开位置。用户 PDF 及截图只存 `.local`，不纳入仓库。尚未完成的完整压力、Windows DPI 和安装验收不得由这些测试推定通过。
