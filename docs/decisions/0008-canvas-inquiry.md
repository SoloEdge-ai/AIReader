# ADR 0008：以问题和证据组织画布问答

状态：阶段 A 已接入，检查范围见[实施记录](../verification/2026-10-20-canvas-inquiry.md)。2026-10-20 用户先要求完善方案，随后授权开始实现。问题卡片及持续探究仍待后续实施。详细流程与验收见[画布问答设计](../plans/canvas-inquiry.md)。

## 背景

当前已有原文摘录、主题组、语义关系、显式材料冻结和回答转笔记。用户希望强化“无限画布 + AI 知识问答”，需要让材料组织、提问、核对和成果复用形成持续工作过程。

本轮源码阅读发现：关系材料已进入冻结流程，但提示词中的材料身份映射不完整；回答转笔记保存历史内容但去掉材料对象 ID；现有检索策略不能直接提供严格的“仅所选材料”。这些是实施前需要解决的契约问题，不是本轮已修复或已运行验证的结果。

## 决定

1. 产品围绕“问题—材料—回答—核对—结论—继续追问”组织。阶段 A 先完成选区快捷提问、范围控制和回答原位保存；问题卡片与结论历史属于阶段 B，跨书研究另行设计。
2. 复用现有画布、Note、唯一正文编辑器和问答浮窗。问题卡片作为长期入口，完整聊天仍在浮窗；AI 来源继续是笔记的来源信息，不复制一套正文系统。
3. 快捷动作准备可编辑草稿，用户明确加入材料、发送问题。选区、位置、主题成员变化不自动修改冻结集合，不静默覆盖已有草稿。
4. “仅所选材料”是 Core 执行的输入、工具和引用边界，默认用于画布快捷动作；“结合本书检索”需要明确选择。已有阅读范围入口继续可用，UI 只展示一个当前有效策略。
5. 来源关系、材料使用记录和用户语义关系分离。“本轮使用了此材料”不意味着它支持结论；空间邻近、软桥和颜色不产生语义判断。AI 关系建议须经用户采纳。
6. 冻结历史与当前对象引用并存。历史负责解释当时依据，当前引用负责定位和版本变化提示；对象删除不清除历史。原文、个人内容、AI 内容在再次提问时继续区分。
7. 回答原位保存通过书籍级原子命令提交 Note、位置、材料关联、回执和逆操作。重复保存复用现有回答笔记，不覆盖用户编辑；失败不显示成功，退出保护与草稿规则继续适用。
8. 继续遵守 book ID 隔离、Renderer 无特权和 Core 所有权。跨书不能通过放宽现有校验实现。新增数据的 schema、归档、复制恢复与版本策略在实施时一并完成，本轮不改变格式版本。

## 取舍

先完成单书的一次可核对探究，使新能力建立在现有阅读与来源优势上。暂不让 AI 自动整理整张画布、自动覆盖结论或自行扩大上下文；这些行为会削弱用户对材料和成果的掌控，也会扩大事务与证据边界。

独立的问题身份有利于长期追问，但会增加会话绑定、结论历史和删除恢复规则，因此放在第二阶段。当前一个对象一个组的空间规则继续有效；多个问题复用同一材料通过引用表达，不先引入多位置复制。

## 与现有决定的关系

延续 [ADR 0004](0004-workspace-groups-and-format-v6.md) 的主题组与真实关系端点、[ADR 0006](0006-continuous-desk.md) 的独立 PDF 与画布交互，以及 [ADR 0007](0007-continuous-source-focus.md) 的连续原文定位。阶段 A 在这些边界内补充问答入口、范围与保存行为，不把旧 ADR 的历史实施状态当作当前代码状态。

阶段 A 采用同次多选集合一次冻结，再用 Core 校验的排除集合实现逐项移除，保证关系端点与材料同版、剩余快照不被重取。材料使用关联保存在 Note 的 origin 并由视图派生，不扩展语义 links 的端点和含义。失去全部画布起点时使用建议空位并允许拖动调整，复用现有交互而不增加落点对话框。

## 验证要求

严格范围必须检查实际模型输入与后续工具调用，不能只测 UI 标签或提示词文本。原位保存必须经真实 Core HTTP/SQLite 验证幂等、原子回滚、撤销、重启、删除与归档恢复；浏览器和 Windows 验收覆盖完整阅读任务、异步切书与保存失败。具体清单见设计方案。本轮仅进行文档和类型/边界检查时，应如实说明其不能证明新功能可用。
